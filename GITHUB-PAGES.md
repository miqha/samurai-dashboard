# Публикация дашборда на GitHub Pages

Готовая папка **`samurai-dashboard-github`** — отдельный проект для загрузки в репозиторий. Загружайте её **содержимое в корень репозитория**, чтобы путь к сценарию был `.github/workflows/pages.yml`. Оборачивать содержимое ещё одной папкой внутри репозитория не нужно.

## 1. Загрузите проект

Проще всего через **GitHub Desktop**: выберите папку `samurai-dashboard-github`, создайте в ней репозиторий и нажмите **Publish repository**. Для бесплатного GitHub Pages выберите публичный репозиторий. GitHub Desktop перенесёт также скрытую папку `.github`.

Если загружаете через браузер, загрузите все файлы и папки, включая **`.github/workflows/pages.yml`** и **`bootstrap/`**. На macOS скрытые файлы показывает **Cmd+Shift+.**. Загрузку можно разбить на несколько коммитов, если браузер ограничивает число файлов за раз. Загружать ZIP в репозиторий вместо распакованных файлов нельзя: GitHub не распакует его автоматически.

Архив `bootstrap/snapshot.tar.gz` хранит проверенный начальный снимок и публичные источники в сжатом виде. Он нужен как обычный файл — **распаковывать перед загрузкой не требуется**. Все файлы подготовленной папки меньше браузерного лимита GitHub 25 МиБ; Git LFS не нужен. Большие тренировочные JS и автономный HTML создаются уже в Actions и не попадают в историю репозитория.

## 2. Включите Actions и Pages

1. В **Settings → Actions → General** разрешите GitHub Actions и стандартные действия `actions/*`, если они отключены политикой аккаунта. Вкладка **Actions** может предложить отдельную кнопку включения — подтвердите её.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**. Ветку `gh-pages` создавать не нужно.
3. Откройте **Actions → «Обновление дашборда и GitHub Pages» → Run workflow**. Выберите основную ветку репозитория и запустите.
4. После успешных задач **build** и **deploy** ссылка на сайт появится в результатах запуска и в **Settings → Pages**. Обычно адрес имеет вид `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.

Название репозитория и логин автоматически используются для ссылки на обновление. Секреты, токены, отдельный сервер и установка Python на вашем компьютере для работы сайта не требуются. Основная ветка может называться произвольно; сценарий определяет её по настройкам репозитория. Если для окружения `github-pages` включено ручное подтверждение публикаций, его придётся подтвердить или изменить правила окружения для автоматических запусков.

## Что обновляется автоматически

Сценарий запускается **каждые шесть часов: в 00:17, 06:17, 12:17 и 18:17 UTC** — это **03:17, 09:17, 15:17 и 21:17 по Москве**. Также он запускается после изменений в основной ветке и вручную через **Run workflow**.

Каждый запуск обновляет историю и составы команды, официальный перфоманс B, каталог и сроки турниров, сложности, авторов, годовой банк тренировок, вопросы отыгранных пакетов и подборки работы над ошибками. Затем проверяет согласованность снимка и публикует статическую версию. Успешные снимки и источники переиспользуются через кеш Actions; при отсутствии кеша достаточно вложенного начального снимка. В репозиторий новые данные не коммитятся.

Если источник недоступен, ограничил запросы или проверка не прошла, **новая версия не публикуется**. Последняя успешная версия сайта продолжает работать. Причина сбоя видна во вкладке Actions. При первом запуске сайт появится только после успешного получения и проверки всех данных.

GitHub может задерживать расписание. В публичном репозитории без активности 60 дней GitHub отключает запуски по расписанию; их можно снова включить во вкладке Actions. Кеш может быть удалён GitHub, поэтому он ускоряет работу, но не является единственным источником данных.

## Кнопка на сайте

На Pages кнопка **«Проверить обновления»** проверяет опубликованную версию и открывает её, если она новее. Рядом доступна ссылка на Actions для полного обновления источников: владельцу репозитория нужно нажать **Run workflow**. Кнопка не запрашивает токены у посетителей.

Каталог перечитывает опубликованный снимок при открытии и каждые 15 минут на видимой вкладке. Истечение и начало уже известных окон игры пересчитываются по часам посетителя. Новые турниры и изменения источников появляются после следующего успешного запуска Actions. Время проверки публикации и время обновления источников показаны отдельно.

История и незавершённые тренировки сохраняются в браузере каждого игрока. Они не передаются в GitHub, не синхронизируются между устройствами и не переносятся автоматически с локального адреса на Pages. Иллюстрации и аудио используют публичные ссылки источника.

## Локальный запуск из скачанного репозитория

Сохраните всю папку, установите Python 3.10+ и запустите **`start-dashboard.command`** на macOS или **`start-dashboard.cmd`** на Windows. При первом запуске начальный снимок распакуется автоматически, затем откроется локальный дашборд с кнопкой полного обновления. `update-dashboard.cmd` сначала восстановит начальный снимок, затем обновит источники. Если macOS не разрешает запуск `.command`, откройте из папки терминал и выполните `python3 scripts/serve.py --open`.

Для автономного просмотра без запуска сервера один раз выполните `python3 scripts/restore_bootstrap.py`, затем откройте созданный **`samurai-dashboard.html`**. Для восстановления начального снимка интернет не нужен. Более свежий полный локальный снимок не заменяется начальным.

## Обновление исходного кода и проверка сборки

Редактируйте исходники в репозитории и отправляйте изменения в основную ветку; Actions пересоберёт сайт. Основной HTML — `index.html`. Настройки обновления — `.github/workflows/pages.yml`. Изменить расписание можно в строке `cron` (часовой пояс UTC).

Для проверки без обращения к источникам:

```sh
python3 scripts/restore_bootstrap.py
python3 scripts/build_pages.py --output _site --repository OWNER/REPOSITORY
```

Замените `OWNER/REPOSITORY` на свой адрес. Папка `_site` содержит только публичные файлы сайта; сценарии, тесты, исходные кеши и журналы в неё не попадают. Можно проверить её обычным статическим сервером. Для деплоя используйте подготовленный workflow, а не загрузку всего репозитория в Pages.

В исходной рабочей папке повторную чистую копию с актуальными данными можно создать командой `python3 scripts/export_github.py --output ../НОВОЕ-ИМЯ-ПАПКИ`. Существующие папки экспорта автоматически не перезаписываются.
