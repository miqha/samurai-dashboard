# Данные и методика

Снимок публичного Rating CHGK для команды **«Самурайская самоизоляция»**, ID **100321**, Санкт-Петербург. Прежнее название в карточке: «Вафля в тесте», до 07.10.2025. Результаты до переименования относятся к той же команде по ID.

Источник: [карточка команды](https://rating.chgk.info/team/100321), публичный API `https://api.rating.chgk.info`. Указанный пользователем адрес `rating.chgk.org` при сборке не разрешался; данные получены с доступного рейтингового сайта и его публичного API по проверенному ID команды. Отдельные профили игроков и их история не загружаются.

## Что загружено

- `GET /teams/100321` — название, город, прежние названия.
- `GET /teams/100321/tournaments` — все регистрации команды.
- `GET /tournaments/{id}` — даты, тип, размеры туров, редакторы, авторские группы и снятые вопросы.
- `GET /tournaments/{id}/results?includeTeamMembers=1&includeMasksAndControversials=1&includeRatingB=1` — публичные результаты, маски и состав команды. Для статистики поля загружается весь турнир.

В снимке **57 регистраций**, **54 опубликованных выступления**, **868 взятых / 2258 действительных вопросов**, **28 игроков в заявленных составах**. Даты начала турниров: 06.09.2024–24.10.2026. Для асинхронов это начало общего окна проведения, а не подтверждённая дата игры нашей команды.

Срез ограничен календарной датой **07.11.2026**. Исключены будущий Полифест-2026 (14150), ещё не опубликованные результаты «Асинхрон Чемпионата Латвии `26. Часть 1» (13764) и «Крафтик №7 (синхрон)» (13452). Они сохранены в данных с `included: false` и причиной `exclusionReason`, чтобы регистрация не превращалась в сыгранный турнир или нулевой результат.

Фактические времена загрузки находятся в `fetchedAt` и `sourceFetchedAt`, дата сборки — в `builtAt`. Исходные timestamps сохраняют UTC (`+00:00`), страница показывает даты по `Europe/Moscow`. Дата отсечения сравнивается с календарной датой старта из исходного timestamp; это срез по дате, не точный исторический снимок всех последующих изменений источника. Последний ресурс загружен 07.11.2026 в 13:05:17 UTC (16:05:17 по Москве). Полнота, исключения и ошибки записаны в `coverage`. Все 114 ресурсов турниров получены; ошибок загрузки и расхождений между собственной маской и официальным числом взятий в исходном снимке нет.

## Вопросы, отмены и поле

`mask` — строка ответов команды. Только символ **`1`** означает взятие, только **`0`** означает невзятие. `X`, `?`, пробел, отсутствующий символ и любые другие значения не превращаются в ноль. Снятые вопросы из `canceledQuestions` — абсолютные номера с единицы — исключаются из всех долей, туров, серий и сравнений. В срезе 4 снятых вопроса; неизвестных символов в действительных собственных масках нет.

`questionQty` — количество вопросов каждого тура, `totalQuestions` — их сумма, включая снятые. `knownQuestions` — число собственных `0` и `1` без снятых; `maskTaken` — сумма единиц на этих вопросах. `score` хранит официальное значение `questionsTotal` из API. Доля взятий вычисляется как сумма взятий / сумма известных действительных вопросов, а не как невзвешенное среднее процентов турниров.

Для каждого вопроса `fieldRates[q-1]` — число единиц, делённое на число известных `0/1` в масках опубликованных результатов **остальных команд этого турнира, без команды 100321**. У каждого вопроса свой знаменатель `fieldCounts[q-1]`: результаты без маски и неизвестные символы исключаются только из соответствующего вопроса. `fieldSuccesses` хранит числитель; у снятых вопросов доля `null`. Если нет ни одного известного ответа соперников, доля также `null`. `fieldSize` — число всех опубликованных результатов с числовым итогом, включая нашу команду; `registeredTeams` — все строки результатов, включая неопубликованные. Распределение итогов `scoreDistribution` также включает нашу команду.

`expectedScore` — сумма долей поля по тем вопросам, где известен собственный ответ. Разность фактических взятий и этого ожидания показывает результат относительно среднего поля на том же наборе вопросов. Это описательное сравнение; оно зависит от состава соперников и не измеряет абсолютную силу или причинный эффект состава игроков.

## Места и перцентили

`position` — официальное место из API; при дележе может быть дробным (например, 96.5). `scoreDistribution` хранит число опубликованных команд с каждым итогом.

Перцентиль учитывает дележ: **100 × (команд с меньшим результатом + (команд с равным результатом − 1) / 2) / (N − 1)**, где `N = fieldSize`. Наша команда исключена из числа равных соперников. Уникальному победителю соответствует 100, последнему месту без дележа — 0. При единственной опубликованной команде сохраняется `null`: сравнение с соперниками не определено. В исходном снимке «Большая механическая» имеет всего 2 опубликованных результата — размер поля необходимо учитывать при выборе лучших выступлений.

Проценты и сравнения маленьких выборок нестабильны. Статистика заявленных составов означает **результат команды при участии игрока**, а не число лично отвеченных им вопросов, вклад в победу или причинное влияние. В заявке бывает 7 человек; API не сообщает, кто сидел за столом на каждом вопросе.

## Авторы и редакторы

`editors` — редакторы всего пакета из карточки турнира. **Редактор пакета не считается автоматически автором каждого вопроса.** `questionCredits` сохраняет опубликованные авторские/редакторские группы: `from` и `to` — первый и последний абсолютный номер диапазона (включительно), `tour` — номер тура. `questions: null` означает весь пакет; `tour: null` — весь пакет или вопросы вне туров в зависимости от диапазона.

Несколько авторов у диапазона — **группа авторов**, а не доказательство индивидуального авторства каждого вопроса. Сравнение таких диапазонов следует показывать с полным названием группы. Только диапазон с одним вопросом даёт привязку непосредственно к вопросу; даже там несколько авторов остаются группой. **В текущем срезе диапазонов одного вопроса нет.** Авторские сведения есть лишь для части истории: в 28 из 54 выступлений опубликованы непустые авторские credits, более общие авторские/редакторские credits есть в 46. Пятьдесят авторских групп покрывают 582 слота, или **580 из 2258 действительных известных вопросов (25.7%)** после снятых; на них 263 взятия. Отсутствие credits означает неизвестное авторство.

Подтверждённый участник credits имеет `id` и `name`; не сопоставленное с профилем имя — `id: null, unmatched: true`; неоднозначное сопоставление — `tentative: true, candidates: [...]`. Кандидаты не считаются соавторами. Исходные credits содержат 2 неоднозначные и 12 несопоставленных авторских записи; среди последних есть явный дефект разбора «Сергей Авторы». Такие записи нельзя выдавать за подтверждённые профили авторов. Отчества и данные тестеров не сохраняются.

Дополнительная проверка `scripts/fetch_authors.py` строит `data/authors-data.json` из готового снимка; после обновления данных её можно повторить. Сохранённая публичная схема credits — `data/authors/api-schema-credits.json`.

## Каталог турниров и доступность в момент просмотра

Каталог хранится отдельно от исторических результатов в `data/catalog.json` и `catalog-data.js`. Его `fetchedAt` — фактическое время последней успешной загрузки; оно не меняет дату среза истории команды. Загрузчик `scripts/fetch_catalog.py` обращается к публичному `GET /tournaments`: `dateEnd[after]` равен UTC-дате запроса, `dateStart[before]` — дате через 90 дней. Нижней границы старта нет: так сохраняются давно начавшиеся длинные асинхроны. Размер страницы — 512, после последней непустой страницы запрашивается пустая; URL, количество строк и дата ответа каждой страницы сохранены в `pagination`. Неполная пагинация не заменяет успешный каталог.

Время запроса фильтрует каталог с точностью до UTC-даты; интерфейс затем проверяет точные timestamps относительно текущего времени устройства. **Начало включено, окончание исключено:** окно открыто, когда `dateStart ≤ now < dateEnd`. Невалидный или отсутствующий интервал остаётся неизвестным. Наступление `dateRequestsAllowedTo` означает завершение приёма заявок; отсутствие поля означает неизвестный дедлайн, а не подтверждённую открытую регистрацию. Учитываются архив, опубликованные признаки отмены, язык и формат. Синхроны, строгие синхроны и асинхроны (ID формата 3, 6, 8) рассматриваются отдельно от очных турниров; для строгого синхрона время и площадку нужно сверять с регламентом.

**Открытое окно проведения не гарантирует возможность сыграть.** API не даёт надёжного общего признака отмены, наличия свободных мест и допуска именно нашей команды. `dateDownloadQuestionsFrom/To` описывают доступ к скачиванию материалов, а не разрешение на отыгрыш. Для регистрации, стоимости, площадки и ограничений следует открыть `regulationsUrl`, `siteUrl` или карточку турнира.

`start-dashboard.command` запускает `scripts/serve.py`, который слушает только `127.0.0.1` и предоставляет `GET /api/catalog` на том же локальном адресе, что и страница. При старте сервер проверяет каталог, а видимая страница повторяет проверку раз в 15 минут и при возвращении на вкладку. Сервер разделяет кэш между запросами; принудительная кнопка также имеет минимальный интервал 15 секунд. Состояния ответа `_live` различают свежий каталог, выполняющуюся загрузку, устаревший снимок после ошибки и отсутствие данных. При ошибке сохраняется последний успешный каталог. После успешной загрузки сервер сохраняет JSON/JS и пересобирает автономный HTML.

В автономном `file://` режиме внешнего запроса каталога нет. Встроенный снимок пересчитывается по часам устройства: истёкшие окна скрываются, наступившие окна из снимка становятся текущими. Изменённые организатором сроки и ещё не известные снимку турниры появятся только после обновления данных. Ошибка часов устройства повлияет на границы доступности.

### Исключение повторов и пересечения вопросов

Сыгранные турниры и регистрации определяются по ID из `data/dashboard.json`; опубликованный нулевой результат также считается сыгранным. Регистрация без результата не превращается в сыгранную игру. При обновлении каталога дополнительно читается полный список ID `GET /teams/100321/tournaments`, который хранится в `teamTournamentIds` с отдельными `teamHistoryCheckedAt`, `teamHistorySource` и `teamHistoryVerified`. При ошибке этой проверки свежий каталог не считается полностью проверенным. Даже если новое выступление ещё не вошло в исторический снимок, его ID уже можно исключить по свежему списку регистраций. Результаты выступлений и калибровка при этом остаются прежними: после новой игры необходимо отдельно обновить историю.

Дополнительно `scripts/fetch_team_intersections.py` читает **`GET /tournaments/{id}/intersections`** для всех ID регистраций в сохранённой истории. По [официальной схеме](https://api.rating.chgk.info/docs.jsonopenapi) это турниры, с которыми пересекаются вопросы; связь ненаправленная, ответ без пагинации, порядок не гарантирован. Сохраняются только исходный ID, `relatedIds`, URL и время получения. Пересечение не означает полного совпадения пакетов и не доказывает, что команда уже видела вопросы из ещё не сыгранной регистрации. Транзитивные пересечения не выводятся.

Проверка 09.11.2026 в 11:50:13 по Москве получила 57 из 57 ресурсов без ошибок: 53 турнира имеют связи, всего 87 связей. Например, у «Крафтик №7 (синхрон)» (13452) официально указан асинхрон 13453. Данные находятся в `data/team-intersections.json`, браузерная версия — `team-intersections.js`. Такие связи позволяют исключать пакет с известным пересечением с историей/заявками из обычных рекомендаций. Общий точный ID GotQuestions также подтверждает повтор пакета. Совпадение названия после удаления обозначения формата остаётся лишь возможным повтором: оно отмечается и исключается из основного списка, но не выдаётся за доказанную связь. Отсутствие опубликованной связи не доказывает отсутствия общих вопросов. Кэш пересечений не обновляется раз в 15 минут; для новых ID команды его нужно обновить отдельной командой.

## GotQuestions, trueDL и сложность отдельных вопросов

Значения сложности хранятся в `data/team-difficulty.json` и `team-difficulty.js`. Источник — публичный `GET /tournaments/{id}` Rating CHGK. В официальной схеме **`trueDL` — фактическая сложность турнира**, **`difficultyForecast` — прогноз организаторов**, **`gotQuestionsTags` — точные ID пакетов `https://gotquestions.online/pack/{id}`**. В базовом историческом загрузчике дополнительные поля не сохранялись, поэтому для них используется отдельный `scripts/fetch_team_difficulty.py`.

trueDL имеет шкалу 0–10, больше — сложнее. [Описание автора](https://pecheny.me/blog/truedl/) привязывает показатель к позиции команд в рейтинге; [репозиторий автора](https://code.pecheny.me/pecheny/truedl) подтверждает использование trueDL на Rating и GotQuestions. Следовательно, значения получены из Rating **по той же шкале, что показывает GotQuestions**, а не представлены как самостоятельно загруженные пользовательские оценки GotQuestions. Лайки и дизлайки не используются как сложность.

В снимке метаданных от 07.11.2026 есть 53 значения trueDL среди 57 карточек; среди 54 опубликованных выступлений — **52**. Точные ссылки GotQuestions получены для 20 турниров через `gotQuestionsTags`; нечёткое совпадение названий для таких ссылок не используется. Один пакет может быть связан с несколькими турнирами с разными значениями trueDL из-за разного поля участников. Значения разных турниров не усредняются как оценки одного пользователя.

Прямой запрос главной страницы GotQuestions 07.11.2026 в 13:48:36 UTC получил **HTTP 429**. Статус сохранён в `data/gotquestions-source-status.json`, выдержки публичной схемы и доказательства общей шкалы — в `data/gotquestions-api-schema.json`, итоговый аудит — в `data/gotquestions.json`. Ограничение не обходилось. Адаптер `scripts/fetch_gotquestions.py` по умолчанию собирает аудит из проверенных кэшей без сети; необязательный `--probe-homepage` делает только проверку доступности и не читает вопросы. Ответ 429 кэшируется минимум на сутки и не повторяется в этом запуске.

**Индивидуальные оценки сложности вопросов GotQuestions не получены.** trueDL турнира не присваивается каждому его вопросу и не заменяет известное авторство. На уровне вопроса используется прежняя `fieldRates` — фактическая доля взятия остальными командами. Эта величина зависит от состава поля; это отдельная метрика, а не trueDL вопроса. Этот адаптер сложности не загружает тексты. Отдельные сборщики получают опубликованные вопросы GotQuestions для тренировок и классификации сыгранных вопросов; наличие открытого окна не разрешает доступ к неопубликованному пакету.

## Как рассчитано соответствие уровню команды

`recommendations-core.js` строит две отдельные убывающие логистические зависимости доли взятия от сложности: для наблюдаемого `trueDL` и для прогноза `difficultyForecast`. В каждой используются последние **24 подходящие опубликованные игры** с известной соответствующей сложностью и действительными ответами команды. Снятые и неизвестные ответы исключаются. Вес старых игр уменьшается вдвое за каждые 8 игр. Для расчёта нужны минимум 6 игр, 120 ответов и диапазон сложности не уже 0.4.

Для нового турнира при наличии берётся фактический trueDL, иначе — прогноз организаторов со своей отдельной калибровкой. Отсутствие сложности или недостаточная обучающая выборка дают «недостаточно данных», а не нулевой прогноз. По умолчанию «по уровню» означает ожидаемое взятие **30–65%**; более доступные пакеты маркируются как разминка, более трудные — как вызов. Внутри списка предпочтение получают турниры ближе к середине заданного диапазона; при равенстве — раньше заканчивающиеся. Ожидаемое число взятых равно прогнозной доле, умноженной на число вопросов пакета.

Это эмпирический ориентир, не официальный рейтинг команды и не гарантия результата. При выходе за обучающий диапазон сложности прогноз является экстраполяцией. Проверка на уже использованной для обучения истории не доказывает точность будущего прогноза: trueDL сам рассчитывается по результатам поля, состав команды меняется, будущие вопросы неизвестны. Значения `mae` и `residualSpread` в модели — ошибки на обучающих играх, а не доверительный интервал и не независимая проверка. При открытом отыгрыше опубликованный trueDL также может измениться после добавления результатов.

## Повторная сборка исторического снимка

Python 3, только стандартная библиотека. Из папки дашборда:

```sh
python3 scripts/fetch_data.py --refresh
```

Фетчер использует 5 параллельных работников (можно `--workers 4`–`6`), до 5 попыток с нарастающей паузой, таймаут 75 секунд. Для нового среза явно задайте календарную дату: `--cutoff 2026-12-01`. Сетевой доступ к публичному API должен быть доступен среде запуска.

Без `--refresh` используются имеющиеся кэши, недостающие ресурсы догружаются. Такой повторный запуск сохраняет исходный срез; для обнаружения новых выступлений и обновления апелляций необходим `--refresh`. При ошибках снимок содержит явный список `coverage.errors`, процесс завершается с кодом 2; отсутствие ошибки сборки не заменяет проверку полноты.

- `data/raw/` — компактные проверяемые кэши с URL и временем получения. Для соперников остаются только ID/название команды, итог, место, маска и признак публикации; их составы, апелляционные ответы и комментарии удаляются до записи на диск.
- `data/dashboard.json` — готовые данные и агрегаты.
- `data.js` — те же данные в `window.SAMURAI_DATA`, чтобы HTML работал напрямую через `file://` без сервера и сетевых запросов.

Структура стабильна: `team`, `fetchedAt`, `builtAt`, `cutoff`, `source`, `tournaments`, `coverage`. В каждом турнире есть исходные метрики, маска, состав, редакторы/авторские группы, распределение итогов и доля взятия поля для каждого вопроса. Неполные результаты не заполняются вымышленными значениями.

История, сложность, пересечения вопросов и каталог обновляются разными загрузчиками. Полная последовательность команд приведена в `README.md`: после обновления истории обновите `fetch_team_difficulty.py`, `fetch_team_intersections.py` и аудит титров, затем каталог и аудит GotQuestions. Последней запускается `scripts/build_standalone.py`, чтобы автономный HTML включал актуальные кэши и код.

## Банк вопросов для тренировок

Активный банк — **9677 опубликованных вопросов из 226 пакетов GotQuestions**, **576 авторов**, по публичному фильтру «Сыграно от/до» за **11.11.2025–11.11.2026**. В том числе: 9507 вопросов ЧГК из 223 пакетов и 170 вопросов СИ из 3 пакетов. В тренажёре по умолчанию выбран формат ЧГК; «Все форматы» открывает и СИ. Даты берутся из самого GotQuestions: у длинных окон начало может предшествовать нижней границе периода. Добавленные недавно старые пакеты вне фильтра не включаются.

Источник списка — публичный [поиск GotQuestions](https://gotquestions.online/search?type=packages&startPlayed=2025-11-11&endPlayed=2026-11-11&sSort=pDate&sortDirection=desc&limit=100). Полнота каталога проверена по метаданным пагинации: 100 + 100 + 26 пакета и пустая четвёртая страница. Сохранены исходные страницы, даты запросов и SHA256 в `data/training-year-sources/catalog/`. `data/training-year-catalog.json` хранит весь список и ожидаемые количества вопросов каждого пакета.

Каждый пакет получен с обычной открытой страницы `https://gotquestions.online/pack/{id}`. Встроенные опубликованные данные Next.js разбираются как JSON без выполнения JavaScript. Длинные тексты и комментарии, которые источник выносит в отдельные записи Flight, разрешаются по идентификаторам и UTF-8 длине. Неизвестная ссылка или несовпадение идентификатора/количества прерывают сборку. Проверяемые кэши всех 226 пакетов, время получения, хеш исходного HTML и хеш публичной записи находятся в `data/training-year-sources/packs/`.

**9677 заявленных = 9677 полученных = 9677 сохранённых**, все ID уникальны. Включены раздатки, дуплеты, вопросы без авторства и без известной сложности, а также вопросы ранее сыгранных командой пакетов. Пропуски и особенности не заменяются догадками. У 3 записей не опубликован ответ, одна из них полностью пуста: эти записи сохранены в архиве с явными признаками источника и недоступны для выбора в тренировке. Поэтому доступны 9674 вопроса, из них 9504 ЧГК. Тексты 9677 записей не влияют на исторические метрики команды.

В базе 1154 вопроса с медиа и 954 вопроса без trueDL. Полные тексты, ответы, зачёт, незачёт, комментарии, источники, авторские идентификаторы и все наблюдения сложности хранятся локально. Иллюстрации и аудио представлены прямыми ссылками GotQuestions: для их просмотра нужен интернет. Материалы ответа и комментария показываются только в разборе после завершения, раздатки — при чтении вопроса. СИ и вопросы с особым регламентом отмечаются отдельно; тренажёр использует общий режим 60 + 10 секунд.

У одного пакета может быть несколько официальных trueDL, относящихся к разным турнирам. Все значения и соответствующие турнирные ID/размеры поля сохраняются в `officialDifficulties`. Для фильтра используется опубликованное значение турнира с наибольшим числом команд; это отдельное исходное наблюдение, не среднее. Неизвестная сложность остаётся `null` и доступна при включении «Все сложности». Авторы в списке сортируются по фамилии, без изменения опубликованного имени.

`data/training.json` и `training-data.js` — один согласованный банк. Чтобы автономная HTML-страница оставалась компактной, вопросы ссылаются на общий список пакетов через `packageId`; при открытии ссылка разрешается без потери полей. Схема снимка — версия 3. Полный объект выбранных вопросов сохраняется в сессии, поэтому прежние тренировки продолжают открываться после обновления банка.

Повторная сборка из проверенных сохранённых записей без сети:

```sh
python3 scripts/fetch_training.py
```

Полное обновление скользящего года (текущая дата по Москве, год назад), каталога и опубликованных пакетов:

```sh
python3 scripts/fetch_training.py --refresh-year
```

Эта же операция включена в общую кнопку «Обновить данные». Запросы отправляются с ограничением частоты. HTTP 429 останавливает загрузку, проверенные кэши сохраняются для продолжения. Неполный банк не публикуется вместо предыдущего. Общий обновитель сохраняет новые данные и автономный HTML только после проверки всего снимка; при ошибке остаётся прежний.

Для продолжения первоначальной загрузки по уже сохранённому каталогу:

```sh
python3 scripts/fetch_training_year.py
```

После сборки данных запускается `scripts/build_standalone.py`. Начальные архивные исходники 2016–2017 годов сохранены для воспроизводимости старой версии; они не подмешиваются в годовую базу.


## Типы сыгранных вопросов GotQuestions

`scripts/fetch_played_questions.py --refresh` читает полный публичный каталог с начала истории команды. Матч пакета — только `gotQuestionsTags` рейтинга либо явная опубликованная ссылка `tIds` GotQuestions. Названия не используются. Дополнительно проверяется полный уникальный ряд номеров 1…N либо точное совпадение туров и локальных номеров. Разминки №0 и явно названные дополнительные туры не входят в основную маску. Несколько возможных пакетов или несовпадение структуры дают явный пропуск.

`data/played-questions.json` и `played-questions-data.js` хранят исходные ID, позицию маски, авторов, признаки, цитаты правил и контрольные суммы. Источники — `data/played-question-sources/`, полный список поиска — `data/played-questions-catalog.json`. Не все игры имеют опубликованную точную ссылку на пакет; охват и список пропусков показаны в интерфейсе. Частичное пересечение вопросов между турнирами не принимается за эквивалентность пакета.

Раздатка: непустые `razdatkaText`, `razdatkaPic`, `razdatkaPicGeneric`; «без раздатки в записи» означает отсутствие полей в источнике. Составные форматы определяются по явным инструкциям в начале вопроса/примечании. Формы ответа — по признакам в тексте, раздатке, примечании и структурированном `form`; цитаты проверяемы по ссылке. Категории формы могут пересекаться; нераспознанное ограничение не считается доказанно отсутствующим. Автоматические правила могут пропускать нестандартные формулировки.

Для сравнения берутся одни вопросы с действительным ответом команды 0/1 и известной долей хотя бы одного соперника. Команда исключена из поля. Каждый вопрос имеет одинаковый вес, а не каждый ответ соперника: среднее `fieldSuccesses / fieldCounts`. Снятые, неизвестные и несопоставленные вопросы исключены из обеих долей. Дуплет или блиц получает один результат рейтинговой маски.

## Авторы тренировок по заявкам

`scripts/fetch_registration_authors.py --refresh` использует проверенный полный список ID турниров команды и свежие снимки истории, каталога и тренировок. Для точно связанного опубликованного пакета берётся объединение авторов его вопросов. Для неопубликованного пакета используется явно подписанная альтернатива — прошлые авторские вопросы объявленных редакторов. Сопоставление личности: официальный ID GotQuestions, опубликованный ID игрока либо уникальное полное имя; неоднозначные имена исключены.

Целевые пакеты и турниры исключаются из подборки. По умолчанию видны текущие и будущие заявки без собственного опубликованного результата; возможность исторического выбора включается отдельно. Срок перепроверяется при запуске. `data/registration-training.json` / `registration-training.js` содержат источники, совпавших и отсутствующих авторов, охват, границы игры и SHA256 всех входных снимков.

Общая кнопка выполняет 10 этапов, включая перепроверку всех годовых пакетов и расширенную классификацию вопросов. Новые файлы публикуются только после проверки хэшей, полноты, соответствия истории и согласованности JSON/JS/HTML. Ошибка оставляет предыдущий полный снимок. Обновление не изменяет сохранённые в браузере результаты тренировок.

Автообновление календаря также проходит через отдельный проверяемый снимок: вместе с каталогом пересобираются связи GotQuestions, метки сыгранных вопросов, авторы заявок и автономный HTML. Свежие авторские подборки передаются открытой вкладке тренировок. История и годовой банк сохраняются. Ошибка любого зависимого расчёта сохраняет предыдущий согласованный календарь.


## Быстрое полное обновление и переносимость

Обновление ведёт две независимые очереди: Rating и годовой архив GotQuestions. Зависимые разборы и HTML строятся после завершения источников. Внутри одного запуска свежие метаданные Rating и список регистраций используются повторно только по квитанции того же UUID запуска; вчерашний кэш не становится свежим из-за совпадения ID или количества вопросов. Годовой архив обязан подтвердить каждый пакет в текущем запуске.

GotQuestions: до трёх одновременных запросов, между началами запросов минимум 0,5 секунды. Проверенные попадания в кэш текущего запуска не ждут сетевую паузу. При HTTP 429 очередь останавливается, срок ожидания сохраняется между запусками и не сокращается. Rating сохраняет общий пейсинг и обработку Retry-After.

Условный HTTP-запрос допускается только для валидного сохранённого пакета с контрольной суммой и выданными сервером ETag/Last-Modified. При 304 `fetchedAt` остаётся временем получения тела, `checkedAt` обозначает новую проверку; при 200 тело и хэш заменяются. Без валидаторов загружается полное тело. gzip распаковывается с ограничением размера. Ошибки, неполная пагинация, несовпадения количества и хэшей оставляют прежний снимок.

Время полного запуска и этапов возвращается в `elapsedSeconds` и `stageSeconds`. Отдельный воспроизводимый замер хранится в `.checks/update-benchmark.json`; его условия важны для интерпретации ускорения. Скорость живых источников и ограничения частоты меняются.

Windows использует те же Python-скрипты и проверки: `start-dashboard.cmd` для локальной страницы, `update-dashboard.cmd` для полного обновления. Скриптам не нужны Node.js, pip-библиотеки или системная tzdata. Передавать нужно всю папку. История тренировок остаётся в браузере получателя.

## Подбор по ошибкам

`focus-core.js` строит `mistakes.tournaments` как объединение top-3 сопоставленных игр по официальной дате начала и top-3 по дате публикации пакета GotQuestions, с устранением повторов по ID турнира. `mistakes.reports[id]` содержит отдельный разбор и строгие тренировочные ID для каждого варианта; тренировочный пул вычисляется один раз. Публикация берётся из `statuses[].publishedAt` в данных сыгранных вопросов: это проверенный timezone-aware `pubDate` исходного пакета. Пропущенная или некорректная дата не заменяется временем получения; охват дат показан отдельно. Все варианты остаются в границах глобального фильтра. `question_types.py` одинаково классифицирует сыгранные и тренировочные вопросы. В годовом банке `classification` содержит структурные категории, а `difficultyObservations` — только проверенные пары целых `correctAnswers` и `teamsCount` одинаковой длины; ID турнира прикрепляется только при подтверждённом соответствии индексов. Некорректные/неполные наблюдения не используются для подбора сложности.

Для каждой категории показаны наша доля, средняя доля остальных команд на тех же вопросах, разница, пропуски и объём. Порог автоматического приоритета — три вопроса, отрицательный разрыв и хотя бы один пропуск. Категории могут пересекаться; дефициты нельзя суммировать. При отсутствии отрицательного разрыва слабость не выдумывается.

Подборка использует строгий список ID `questionIds`: отсутствие подходящих записей даёт пустой результат, без расширения категории или замены её авторским подбором. Исходный турнир и категория сохраняются в тренировке и её итогах. Известные сыгранные вопросы/пакеты и снятые вопросы исключены; неизвестные повторы из несопоставленных турниров возможны.


Проверка 17.11.2026: полное живое обновление завершилось за **251,116 с (4 мин 11 с)**, перепроверены **223 из 223 пакетов**, опубликован согласованный снимок из 397 файлов. Результат и длительности этапов: `.checks/update-live-result.json`.

Контрольный офлайн-прогон на одних сохранённых ответах: **13,010 → 4,861 с (2,676×)**, 490 → 431 запроса, 24,04 → 5,45 МБ. Сетевое время масштабировано, CPU-обработка и проверки выполняются в реальном времени; это не измерение старой и новой версий на живом сайте. Все разобранные записи совпали. В реальном обновлении все пакеты получили HTTP 200: источник сейчас не выдаёт валидаторы, поэтому выигрыш от HTTP 304 не приписывается замеру.

Для повторения без сети: `python3 scripts/benchmark_update.py`. Исходная версия планировщика — `benchmarks/baseline/update_dashboard.py`; фиксированная выборка публичных ответов — `.checks/update-benchmark-inputs.zip`. Полные условия и хэши — `.checks/update-benchmark.json`.
